Builds Enshrouded blueprints from 3D shapes and exports them as `.ebblueprint` files for Embervale Toolkit.

**Version 0.53.2.** Combine any of 35 shapes (19 of them 2D shapes that lie flat or stand upright, one block thick or cylinderized), six kinds of roof and imported blueprints into one build, see it on the game's 0.5 m grid in a 3D view, undo and redo changes, save it as a project you can reopen, and export it. Roofs use the game's own 45° roof pieces, or blocks at other angles (per arm on L, T and cross roofs, any angle or a rise/run pitch on gables and sheds) and heights, single, double or triple thick, with optional edging in another material, and gables that fit under any gable or shed roof's ends. The window title shows the version. See [Version history](#version-history) for what changed in each version.

## Run it (Windows)

You need [Node.js](https://nodejs.org) 20 or newer.

```
cd shapeforge
npm install
npm start
```

`npm start` builds into `dist/` and opens the app. Across the top is the ribbon, with the ShapeForge logo at its left (click it, or **About**, for the version, author and credits): **Project** (New, Open, Save, Save as, with the project's file name at the left; hover it for the full path), **Edit** (Undo, Redo), **View** (Settings, About, Fit view) and **Export** (the blueprint **Name**: the project file's name, shown greyed, until you type one of your own; clear it to follow the file again; where it lands in game (**Anchor** and **Lift**), **Use larger pieces** and **Export**), then the stats and messages. Below it, the selected shape's settings are in the left sidebar, the view in the middle and the shape list in the right sidebar. Drag the line between a sidebar and the view to make the sidebar wider or narrower (or focus it and use the arrow keys; double-click it to go back to the usual width); the widths are remembered, and the view always keeps at least 280 px. In the window:

1. **Add shapes.** Pick a shape under Shapes (in the right sidebar) (grouped as 2D shapes, 3D shapes and Roofs) and click **Add**. It appears in the list, resting on the ground at the center.
2. **Edit the selected shape.** Click a shape in the list (its outline shows in orange in the view). Set its position (the shape's center), rotation, size, filled or hollow, line weight and material. A hollow shape's wall is **Wall thickness** blocks deep, measured straight in from its surface, so it is equally thick on tilted, curved and flat walls; **Thick** line weight also keeps blocks that touch the outside only at an edge or corner, which seals the wall.
3. **Materials.** The material list has two groups: **Building blocks** (74) and **Terrain** (61). Any shape can use either.
4. **Combine.** Each shape can **Add** blocks, **Subtract** from the shapes above it in the list, or **Keep only the overlap** with them. Use **Up** and **Down** to change the order, **Duplicate** to copy a shape, and **Delete** (or the Delete key) to remove one.
5. **Organize.** See [The shape list](#the-shape-list): name shapes, and group them in folders.
6. **Export.** Click **Export** in the ribbon and save the file where Embervale keeps its blueprints. By default the export uses larger pieces (Foundations, Walls, Ceilings, Columns) wherever they fit exactly, so the same blocks take far fewer pieces; the stats line shows both counts. Untick **Use larger pieces** beside it if you ever want plain cubes; the setting is remembered.
7. **Save your project.** In the ribbon's Project group, **Save** (Ctrl+S) writes a `.shapeforge` file (Open also accepts the `.shapeforge.json` files saved by versions 0.3 to 0.5) with every shape and its settings; **Open** (Ctrl+O) loads one back for editing, and **New** (Ctrl+N) starts another; both open in a tab of their own beside the files already open (see **Open files and settings** below). The window title shows the file name, with `*` when there are unsaved changes, and the app asks before closing a file or the window with unsaved changes. Export a fresh `.ebblueprint` whenever you want to use the latest version in game; the blueprint itself can't be reopened for editing.

**Open files and settings.** You can have several projects open at once. **New** and **Open** add a tab for the file (or use the current one if it's an untouched Untitled; opening a file that's already open just switches to it). The tab bar shows above the ribbon only while more than one file is open: click a tab to switch (each keeps its own shapes, selection, undo history and camera view), Ctrl+Tab and Ctrl+Shift+Tab go to the next and previous, and **×**, a middle-click or Ctrl+W closes one, asking first if it has unsaved changes (a dot • on the tab). **Settings** in the View group sets the **Theme** (System, the default, reads Windows' own settings in Settings > Personalization > Colors and is light only when Windows plainly asks for light: the app mode is Light and the Windows mode isn't Dark. With Custom set to a dark Windows mode and light apps, or if the setting can't be read, it is dark. Under System, Settings shows what it read. It follows a change while ShapeForge is open. Or choose always Light or always Dark; the title bar matches) and **Reopen the files I had open when ShapeForge starts** (on by default): the saved files open in tabs again, with the one you were on in front, and the status line names any that have since been moved or deleted. Unsaved Untitled files aren't reopened. Settings are kept on this computer.

**About.** **About** in the View group (or the logo at the left of the ribbon) shows the version, the author (JamGobbar, shapeforge.software@gmail.com; the address opens your mail program) and credits, and **Open the README** shows this README in a tab of its own beside your files (as it was for the version you're running; links to its sections work, and web links open in your browser). While the README tab is in front, your project waits behind it and the ribbon's project tools rest; click the project's tab (or Ctrl+Tab) to go back, and close the README with its × or Ctrl+W. The logo is `src/renderer/logo.svg`; the window and taskbar icon, `build/icon.ico` (16 to 256 px) and `build/icon.png` (512 px), are drawn from it.

**Import an existing blueprint.** **Import .ebblueprint…** under Shapes adds any `.ebblueprint` (from your image interpreter, Embervale, or an earlier export) to the list as an *imported layer*. It works like a shape: move it, turn it (in 90° steps, so blocks stay on the grid), hollow it, or add, subtract and intersect it with other shapes. By default it keeps each block's own material; pick a material to recolor all of it. Every block piece type is read, including Door Frames, Walls, Ceilings, Columns and Foundations, which are split into 0.5 m blocks. The layer is saved inside your project, so the original file isn't needed afterward.

**Undo** (Ctrl+Z) and **Redo** (Ctrl+Y or Ctrl+Shift+Z) cover every change to the shapes and the blueprint name. Quick edits to one field, like typing a number, undo as one step. Undoing back to your last save clears the unsaved-changes marker. Each open file has its own history; opening a project or starting a new one starts a fresh one.

Shapes:
- **2D shapes:** regular polygon, ellipse, ring, arc, pill, rounded rectangle, superellipse, crescent, lens, heart, teardrop, shield, rose curve, leaf, arch outline, grid, gear, plus the extruded star and flat vortex.
- **3D shapes:** spheroid, squashed sphere, capsule, teardrop (round at the bottom, tapering to a point on top: **Width** at the widest, **Height**, and **Point**, higher for a longer, sharper tip; turn it with Rotation to point it down or sideways), cube/box, slanted box (rhomboid), cylinder, cone/frustum (round), 4-sided pyramid, frustum (cut pyramid), 3-sided pyramid, extruded trapezoid, spiky 3D star, helix, saddle sheet and polyhedron.

**Uncapping.** Hollow 3D shapes can open their ends with the **Uncap ends** toggle buttons (−x, +x, Bottom, Top, −z, +z; a lit button is an open end), each end in the shape's own frame (so a turned shape opens at its own ends): spheroids, squashed spheres and capsules on all six ends, boxes and slanted boxes on all six faces, cylinders, cones, frustums, extruded trapezoids and extruded stars at the top and bottom, and the pyramids at the bottom. A round end (spheroid, squashed sphere, capsule) is cut off to the **Uncap depth** (meters in from that end); a flat end loses its wall while the side walls run on to the edge, making an open-topped box, a tunnel or a bowl (the shape is carried on past the open end before it is hollowed, so only blocks that are surface because of that end come off; this works at any rotation, and a stepped slope such as a wide cone's is never touched). A cone or frustum with no top comes to a point, so uncapping its top cuts the tip off to an **Uncap depth**. Uncapping is only offered for hollow shapes; filled ones hide and ignore it.

### 2D shapes

Every 2D shape has the same settings, as toggle buttons:
- **Lying / Standing:** flat on the ground (its outline across x and z) or upright (across x and y, facing z). Arch outline, shield, grid, heart, teardrop, gear and extruded star stand by default; the rest lie flat. Use the shape's rotation for any other angle.
- **Flat / Cylinderized:** one block thick, or with a **Thickness** (its height when lying, its depth when standing).
- **Filled / Hollow:** hollow and flat, the shape is its outline (the wall thickness measured across it); hollow and cylinderized, it is a closed shell. A hollow cylinderized shape thicker than one block can uncap its two faces (**Bottom / Top** when lying, **Back / Front** when standing), leaving the side wall full height, like an open tube or tray. The arc can also open its two cut ends (**Start / End**), and the arch frame its **Base**. The crescent and the grid have nothing to uncap.

The shapes and their own settings:

Drag to orbit the view, right-drag to pan, scroll to zoom. **Fit view** frames the whole model.

**Moving the camera with keys.** **W A S D** move the view and **Page Up** / **Page Down** raise and lower it, while held; hold **Shift** to go about three times as fast. What W A S D do is set under **WASD** in the ribbon's View group: **Fly** (the default; W and S move forward and back the way you're facing, A and D slide sideways, staying level) or **Orbit** (A and D swing round the middle of the view, W and S zoom in and out). The keys do nothing while you're typing in a box.

**Tools** (in the ribbon; or press **H**, **V**, **M**, **R** or **P**, shown on each button) set what a left drag or click does in the 3D view. In every tool but Navigate, right-drag turns the view, middle-drag pans and the wheel zooms.

- **Navigate** (H): the view as usual.
- **Select** (V): click a shape to select it, as in the shape list (Ctrl-click adds or takes out one, Shift-click a range); clicking empty space clears the selection. A click picks the shape whose block you see there (a shape cut away by a subtract isn't picked; a roof is picked by its box). Drag a box to select every shape with any part inside it, as seen from where you are (Ctrl or Shift to add to the selection); shapes behind others count too.
- **Move** (M): drag to slide the selected shape or shapes level, in 0.5 m steps; hold **Ctrl** to move them straight up or down instead (you can press and let go of Ctrl mid-drag). Dragging a shape that isn't selected selects it first.
- **Rotate** (R): drag left or right to turn the selection about the vertical axis (to the right turns it clockwise seen from above, half a degree a pixel); hold **Ctrl** to tilt it about x or **Alt** to roll it about z. Several shapes turn together round their middle, as one piece. Turns go in 5° steps; with an imported layer selected, in quarter turns; with a roof selected, only quarter turns about the vertical axis (roofs only face the four directions), and tilting or rolling says why it can't. The status line shows the turn as you drag.

While you drag with Move or Rotate the shapes themselves move and turn as you go (not just their outline), so you see the result before you let go.

The **Rotation** settings of a shape have a **Reset** button that sets them back to 0, 0, 0; with several shapes selected, Reset puts them back as they were when you selected them.

- **Anchor** (P): click the block the blueprint lands on in game (see [Where it lands in game](#where-it-lands-in-game)). Click a block of the build to use it; **Shift**-click a block for a marker block on the face you clicked; click empty space for a marker block level with the build's lowest blocks, where you clicked.

A Move or Rotate drag is one undo step, and so is each anchor change.

## Where it lands in game

In Embervale you place a blueprint by putting down a block: the blueprint's **first piece** takes that block's place, and the rest of the build lands round it. (Tested in game: the file's `anchorMode` and `anchor` make no difference; only the first piece does.) ShapeForge chooses that first piece:

- **Auto** (the default): the lowest block nearest the middle of the build's footprint, so the build lands roughly centred, sitting on your block.
- **A block of the build**, picked with the Anchor tool: for example the doorstep, or a corner to line the build up with a wall.
- **A marker block** in empty space (picked with the Anchor tool): in front of a door, in the middle of a courtyard, under a raised build. It's a Yellow Luminescent block, shown in the view; in game it takes the place of the block you put down, so after placing you delete just that one block (the rest of the build stays as it is).

The anchor is written as a single block, kept out of larger pieces, so it lands exactly. The ribbon shows which kind it is (hover for where); **Auto** beside it goes back to the default. With the Anchor tool chosen, the view marks the anchor with an outline and a pin (pale blue when it's the default, yellow once picked); with other tools only a picked anchor is marked.

**Lift** (meters) raises the build that far above your block (negative lowers it): the file's `lift`, which Embervale honours. For example, anchor a house on its ground floor and lift it 0 m, or anchor a marker at the bottom of a cellar and lift it to sink the cellar below ground.

The anchor and lift are saved with the project.

## Scale

Shapes with two or more sizes (width, height, depth, radii, ...) have **Scale (%, all sizes together)** at the top of their Size settings, with **½×** and **2×** buttons: every size in meters changes together, so the shape grows or shrinks in proportion. Each size keeps to its 0.5 m steps and its limits (the status line says when one hits its limit and the proportions shift a little). Scale works from the sizes the shape had when you started scaling, so going to 150% and back to 100% gives the original exactly; editing a size yourself, or picking another shape, starts again from 100%. Wall thickness, counts, angles and pattern sizes stay as they are. Roofs, pipes, gables and text keep their own size settings, and shapes with one size (a regular polygon) don't need it.

## Patterns

Every shape built from blocks (not roofs or imported layers) has a **Pattern** section: a second **Pattern material** laid across some of its blocks, the rest staying in the shape's material. A pattern only chooses materials; the blocks are the shape's own. It's centred on the shape and moves and turns with it.

- **Checkerboard** (square size), **Stripes** (width; across, up and down, or either diagonal; or **Swirl**: stripes running from pole to pole round the shape, like a twisted sweet or candy kiss, with **Stripes around**, **Twist** in turns from bottom to top, which way they **Turn**, and **Stripe share** of the surface; round the shape's up, or round z or x when laid on the front or side), **Rings** (width), **Concentric polygons** (width, 3 to 12 sides), **Spiral** (band width, 1 to 8 arms, either way round).
- **Maze**: a true maze (every path reaches every other, no loops) filling the shape, paths in the shape's material and walls in the pattern material; **Path width**, and **Variation** for a different maze.
- **Flagstones**: irregular stones in the shape's material with joints in the pattern material; **Stone size**, **Joint width**, **Variation**.
- **Herringbone** and **Basketweave**: bricks **Brick width** blocks wide and **Brick length** widths long. **Joints** (the default) outlines each brick with a one-block joint in the pattern material (bricks 2 or more blocks wide); **Two-tone** colours them instead (herringbone: one way in one material, the other way in the other; basketweave: alternating within each square).
- **Laid on**: **Auto** puts the pattern on a 3D shape's **skin**: each block on the surface takes the pattern of the face it shows on (a cube gets it on all six faces), as far in as **Depth** says (1 block to start), the inside staying plain; where a block shows on two faces at an edge, the top wins, then the bottom, front, back and sides. On a 2D shape Auto is its own face. **Skin** does the same for any shape. **Top**, **Front** and **Side** draw it on that plane, running straight through the shape. **3D** makes checkerboard, rings and polygons three-dimensional (cubes, spherical shells, nested boxes). On round shapes the skin takes each patch of surface from the side it mostly faces, so the pattern changes where those patches meet. On a solid sphere 3D rings show one material (its whole surface is in one shell); they show on boxes or cut and hollow shapes.

A die's numbers and a gable's blocks against roof pieces keep their own materials over a pattern.

## Polyhedron

The five Platonic solids and the standard dice: **Tetrahedron** (d4), **Cube** (d6), **Octahedron** (d8), **Pentagonal trapezohedron** (d10), **Dodecahedron** (d12) and **Icosahedron** (d20, the default).

- **Stands on**: a **Face** (as a die rests), an **Edge** or a **Point** (a corner; the d10's tip), straight down.
- **Number on top** (standing on a face): which numbered face is up, the one opposite underneath; on a d4, which number is at its top corner (the roll). The highest to start. The top face lies square on the block grid, so with numbers on, its number reads crisply.
- **Height as it stands**, in meters: from the bottom to the top as it stands, so a d10 on its tip is narrower than one lying on a face at the same height. Pointed tops lose their last half block, as on a cone.
- **Faces**: **Closed**, filled or hollow like other 3D shapes, or **Wireframe**: only the edges, the faces left open. Each edge is a bar **Edge thickness** blocks wide on both faces it joins and as deep, inside the solid's outline, so the frame is the same size as the solid with flat outer sides (a cube's bars are square). Filled or hollow doesn't apply to a wireframe.
- Turn it to any angle with Rotation as usual.

**Numbers** (**Faces numbered: Yes**) number the faces like real dice, in their own **Material** (Hollow Halls Block, nearly black, to start), using the blocks the faces already have (a wireframe gets them added in its open faces, so they show there too):

- Opposite faces add up as on real dice: d6 to 7, d8 to 9, d12 to 13, d20 to 21. The d6 is the usual right-handed die, 1, 2 and 3 counterclockwise round the corner they share. The d10 runs 0 to 9 (or **d10's ten: 10**), opposite faces adding to 9, the odd numbers round one tip and the even round the other, each standing with its top toward its kite's tip. The d20 has 20 with 2, 8 and 14 round it (and 1 with 19, 13 and 7); the d8, d12 and the rest of the d20 are spread so the faces round each corner add up as evenly as they can. The d4 has a number in each corner of each face, pointing at it: the number at the top is the roll (right-handed: 1, 2 and 3 clockwise on their face). 6 and 9 are underlined on dice that have both.
- A d6 can have **Dots** instead, in the usual patterns.
- **Font**: any of the built-in fonts; Tiny5, the smallest, to start. All the numbers on a die are the same size, as big as fits the faces at **Size** (percent). A pixel font keeps its pixels a whole number of blocks (at least one), so on small faces its numbers can be bigger than the face. On a face square to the block grid (the top of a die standing on a face, or any d6 face) numbers line up with the grid and read crisply; on slanted faces they're rougher, so for legible numbers make the die bigger or try a bolder font (Bungee, Black Ops One).
- **Depth**: how many blocks in from the face the numbers go (1 to start).

A wireframe needs room for its openings: with 2-block edges, a d10 or d20 opens up well from about 20 m tall (their faces are small for their height); a cube or dodecahedron already at 8 to 12 m. One-block edges on a slant can come out patchy, since a 0.5 m bar at an angle is thinner than a block.

The d10's usual shape is the one exactly opposite a pentagonal antiprism with equal edges. **Width (d10)**: **Natural** keeps that shape; **Custom** sets its **Width across the middle** (corner to corner, square to the line through its tips) separately from its height: the faces tilt to fit, so it gets squatter or more pointed, with all ten kites still alike (still a fair die). Height as it stands stays as set; a very pointed d10 loses up to a meter at each sharp tip, where it's narrower than a block's middle. Lying on a face, a d10 can't be made much narrower than its natural width (the faces would have to stand up), so it stops at the nearest it can make.

## Text

**Text** (its own heading in the Add menu) builds words from blocks in one of 17 built-in fonts. Type in the **Text** box; Enter starts a new line. It's a 2D shape like the others: **Standing upright** (the default, like a sign) or **Lying flat** (reading the right way from above), **Flat** (one block thick) or **Cylinderized** to a thickness, and **Filled** (the default) or **Hollow** (the letters' outlines).

- **Font**, in five sets (each labelled with the letters it has: all European accents, most of them, or Western European only, plus Greek and Cyrillic where it has them; the line under the text box says the same and names some of the letters a font lacks): small and readable pixel fonts (Tiny5, Micro 5, Silkscreen, Press Start 2P), block letters (Bungee, Black Ops One, Anton), medieval and fantasy (Cinzel, UnifrakturMaguntia, Pirata One, Grenze Gotisch, New Rocker), sci-fi and modern (Orbitron, Audiowide), and graffiti (Permanent Marker, Sedgwick Ave Display, Rubik Spray Paint).
- **Weight**, for the fonts that have more than one (Silkscreen: Regular and Bold; Cinzel, Grenze Gotisch and Orbitron: Regular, Bold and Black). It starts at the heaviest, which holds up best as blocks; the weight you choose is kept, and a font without it uses its nearest.
- **Letter height**, in blocks: the height of a capital. Pixel fonts keep each of their own pixels a whole number of blocks, so their letter height goes in steps of their capital height in pixels (5 for Tiny5 and Micro 5, for example: 5, 10, 15 blocks); the line under the text box says what it comes to. Small text reads best in the pixel fonts (5 to 8 blocks tall); the others need about 10 blocks or more, and the detailed medieval and graffiti fonts 16 or more.
- **Extra space between letters**, in blocks (negative to tighten). With more than one line, **Extra space between lines** and **Lines line up**: left, middle, right, or **justified** (every line but the last stretched to the full width, the extra space shared between its words, in whole blocks for a pixel font; the last line, and a line of one word, stays on the left). Spaces at the end of a line don't count toward its width.
- Letters are spaced by the font's own widths and kerning. Characters a font hasn't got are left out, and the line under the text box names them.
- Each font carries everything it has of: Latin in all its accented and extended forms, Greek, Cyrillic, punctuation, currency, arrows, maths, technical signs, box drawing, shapes, symbols and dingbats (not right-to-left or joined scripts, which need text shaping). How much varies a lot: Tiny5 has Greek, Cyrillic, arrows and shapes; Press Start 2P has Greek and Cyrillic; Bungee arrows and shapes; most have the accented letters of every European language.
- **Symbol fonts**: a symbol the chosen font hasn't got is borrowed (letters of the Latin, Greek and Cyrillic alphabets never are, as a letter in another font's style would stand out in a word: they're left out and named under the text box) from ten built-in symbol fonts, in this order: Noto Sans Symbols 2 (arrows, chess, cards, dominoes, mahjong, shapes, Braille, ornaments), Noto Sans Symbols (alchemy, zodiac, circled letters, technical signs), Noto Sans Math (operators and fancy maths letters: Fraktur, script, double-struck), Noto Music, Noto Sans Runic, Noto Sans Glagolitic, Noto Sans Linear B, Noto Sans Egyptian Hieroglyphs, Noto Sans Anatolian Hieroglyphs and Noto Emoji (animals, food, tools, buildings and more, as outlines). A borrowed symbol is drawn at the same size as the letters (the same em) on the same baseline, so "⚔ EMBER HALL ⚔" in Cinzel just works; in a pixel font it moves the next letter on by whole blocks so the letters stay on their pixel grid. Thin line art (the hieroglyphs, the runes) needs bigger text to hold together: 30 blocks or more for hieroglyphs.
- **Symbols…** under the text box opens a picker of everything the text can show beyond plain letters and digits, about 11,000 symbols in 33 groups under five headings: Letters (accented, Greek, Cyrillic, runes, Glagolitic, fancy maths letters), Signs (punctuation, numbers and money, circled and boxed, arrows, maths, technical, lines and blocks, shapes, Braille), Symbols (symbols, dingbats and ornaments, chess, playing cards, dominoes, mahjong, alchemy, music), Pictures (nature and things, faces and people, travel and places, more pictures) and Ancient (Egyptian and Anatolian hieroglyphs, Linear B, ancient signs). Each is drawn from the font that will build it (hover for its code and which symbol font it comes from); click one to put it in the text at the cursor. Anything you paste or type works too.
- The text's box is always an even number of blocks each way, so on the usual 0.5 m positions every letter lands on the block grid the same way wherever it's moved.

The fonts are free fonts from Google Fonts, shipped under their own licences (in `fonts/`, one folder per family): the SIL Open Font License 1.1 (all the symbol fonts too), and the Apache License 2.0 for Permanent Marker. `tools/build-fonts.py` turns them into letter outlines in `src/core/fonts/` (it needs Python with fontTools); run it again after changing the files in `fonts/`.

## The shape list

The list is in the right sidebar and fills its height, scrolling once it's longer than that, and sideways once a row (deep in folders or pipe branches) is wider than the sidebar; widen the sidebar by dragging its edge.

- **Names.** Double-click a shape (or press F2) to rename it in the list, or type in **Name** at the top of its settings. A named shape shows its kind beside its name; clear the name to go back to just the kind.
- **Folders.** **New folder** makes a folder where the selected shape or folder is, holding it, and names it straight away. Folders nest. Click a folder's arrow (or press the right and left arrow keys on it) to open or close it; the number beside it is how many shapes are inside, however deep.
- **Moving.** Drag a row onto a folder's middle to put it inside, or onto the top or bottom edge of a row to put it just above or below; a line or a lit-up folder shows where it will land. Drop below the last row for the end of the list. **In folder** in a shape's or folder's settings moves it into a folder (at its end) too. **Up** and **Down** move the selected shape or folder past the next item beside it, within its folder.
- **Order still counts.** Shapes apply top to bottom whatever folders they're in: a folder's shapes always stay together, so a folder is a run of the list where its first shape is, and a subtract or intersect shape cuts every shape above it, in or out of folders. An empty folder stands at the end of the folder it's in until it holds something.
- **A selected folder** shows a box round everything in it in the view, and its settings have the same **Position** and **Turn the folder** controls as a multi-selection (see below), for moving and turning everything in it as one piece (Position only when a roof is inside). **Duplicate** copies the folder and everything in it (the copies set 1 m aside), **Ungroup** removes the folder and keeps its shapes where they were, and **Delete with its shapes** (or Delete) removes it all, after asking.
- **Selecting several.** Ctrl-click (Cmd on a Mac) adds a shape or folder to the selection, or takes it out; Shift-click selects everything listed from the last item clicked to this one (Ctrl+Shift-click adds that range). A selected folder brings everything in it. The view boxes the whole selection, and the settings panel changes to the group's: **Position** is the middle of the box round them all, and changing it moves them all together; **Turn the group** turns them round that middle as one piece (each shape's own rotation turns with it; imported layers keep to quarter turns, so the turn goes in 90° steps when one is selected). Roofs only face the four directions, so with a roof in the selection only Position is shown. **Delete** removes the whole selection, after asking; Duplicate, Up, Down and New folder work on one item at a time. A plain click (or Escape in the list) selects just one again.
- New and imported shapes go at the end of the selected folder, or of the selected shape's folder.
- Names and folders, open or closed, are saved with the project; they don't change the blueprint.

## Turning the whole build

**Turn all 90° ⟲ / ⟳** (under the shape list) turns every shape a quarter turn counterclockwise or clockwise, seen from above, around the middle of the build, so the exported blueprint faces another way. It is one undo step. Each shape keeps its look: other shapes and imported layers turn with their own rotation; roofs change their facing (a gable's or hip's half turn mirrors its saltbox side and off-center ridge instead, since those two only face along x or z), a cross roof's arms trade places, and gable ends chosen by world direction (Recede at gable ends) follow the turn. The middle is on the 0.5 m grid, and roofs and imported layers are lined up by their blocks, so every block and roof piece lands exactly where the old one turned would (`tests/rotate.test.ts` checks this). A shape at an odd angle can gain or lose a block where a surface passes exactly through block centers.

## Roofs

Six roof shapes: **shed** (one slope), **gable** (two slopes), **hip or pyramid** (four slopes; a ridge length of 0 makes a pyramid), and **L-shaped**, **T-shaped** and **cross-shaped** roofs (wings of equal width meeting at valleys, with a hip on the outside of an L's bend). Roof materials are listed first in the material picker. Roofs are always added as they are, so Combine, rotation, hollow and line weight don't apply to them; place a roof on your walls by its position (the center of the roof's box).

- **Size.** Pick the piece size (2 m or 4 m roof pieces), the rows up each slope (which sets the width), and the length along the ridge. **Lengths in** switches between pieces and meters; in meters, lengths go in 0.5 m steps. For a length that isn't a whole number of pieces, the pieces at the end slide back over their neighbors, which share the same slope. An end too short to slide back without reaching into a bend (a hip end needs one plain piece before it) rounds up to whole pieces.
- **Arms (L, T and cross roofs).** Their settings are in tabs: **Roof** (name, folder, position, piece size, lengths in, material, then what applies to the whole roof: edging, layers, recede and turn) and one tab for each arm, such as **Bar -x arm**, **Bar +x arm** and **Stem along +z** on a T. The tab you're on stays put while you edit and is remembered for each roof; the left and right arrow keys move between tabs. Each arm has its own settings, in its tab under its name (starting with its own **Angle**: 45° roof pieces, 22.5°, 33.3°, 67.5° or set by its height), with a **Reset** button that puts just that arm back as it was when the shape was created (Undo brings it back); a line separates the arms from the general settings after them: **Length past the junction**, **Width** (rows up each slope with roof pieces, or meters in 0.5 m steps once the roof is built from blocks), **Height**, **Offset sideways** (every arm but a T's stem, which stays centered on the bar; always in meters, 0.5 m steps; slides just that arm along the arms it joins, for staggered arms, until its outer edge (eave included) is flush with those arms' ends: each way is limited by the arm running that way, and where none does (an L's outside corner, the far side of a T's bar) not at all, so an arm never slides off the roof it joins), and **End** (gable or hip). Arms of different widths stay roof pieces at 45°, each ridge as high as its own width; a narrower arm's ridge runs into the taller roof with valleys. Arms straight across from each other (a T's bar, a cross's pairs) each cover only their own half: they stop at the junction's center line, where lined-up arms' ridges meet and run straight through, and moving or resizing one never changes the other side (a taller arm ends there in an open gable, with room under it for a Gable shape; a block roof no longer builds a wall down to the lower arm there). Arms with nothing across from them (an L's arms, a T's stem) reach over the junction to the far edge of the arms they cross and end in a hip there (the outside corner of an L). Offsetting the arm they cross slides it along them: they keep their length, and where it slid inward they carry on past it to a plain gable end; where it slid past their end, they grow to meet it. A T's stem does this in two halves, one for each bar arm, both ending in a hip in one straight line at the bar's far edge (the furthest of the two bar arms where they are now), so widening or sliding one bar arm never leaves one half of the stem longer than the other. An arm whose end lands inside another arm (two arms slid to meet end to end) carries on to that arm's far edge and ends in a hip, so the outside corner between them gets a shoulder like an ordinary L's corner. After laying out roof pieces, ShapeForge checks every piece's overhanging eave against the piece owning the ground below it: a poking piece that is extra is left out, and a junction where an eave would stand more than 0.5 m proud is built from blocks instead. (A valley's eave over a short hip end can stand up to 0.5 m proud; plain L and T roofs have always had this.) Any arm at another angle, typing an arm's height (which sets just that arm to "set by height"), or an offset that isn't a whole number of pieces builds the whole roof from blocks, with each arm keeping its size and its own slope; the roof only uses roof pieces while every arm is at 45°. Projects saved before 0.15 open with their one roof angle on every arm. L and T roofs can be turned in quarter turns.
- **Turning.** A gable's or hip's ridge runs along x or z; a shed's high side can face any of four ways.
- **Roof angle.** 45° (the default) uses the game's roof pieces. 22.5°, 33.3° and 67.5° build the same roof from blocks in its material, over the same plan. Each slope's rise is its run (in blocks, eave to ridge) times the angle's tangent, rounded to whole blocks, so small roofs only approximate the angle; the editor shows the angle as built. Gables and sheds also offer **Custom angle** (any angle from 1° to 89°, in 0.1° steps) and **Rise / run** (a pitch such as 6 in 12, in 0.5 steps); both are built from blocks as closely as the roof's size allows, and the editor shows what it aimed for next to what it built. L, T and cross roofs set the angle per arm (see Arms).
- **Roof height.** Always shown. On a 45° roof it shows the height the pieces give; typing a new height (in 0.5 m steps) switches the roof to **Set by height**, built from blocks with the slope that height gives over the roof's width.
- **Edging.** Every roof can have **Edging** in another material (**Edging material**) along the ridge, the eaves and, if chosen, the gable ends (**Edging along the ridge / eaves / gable ends**). A roof piece is one material, so on a 45° roof the edging is whole pieces: the eave row (sloping down to the eaves, hip corners included), the ridge row (nothing of the roof higher over it) and the pieces at each gable end. On a block roof it is one block wide: the eave columns, the ridge column (one or two wide) and the gable-end columns. On a roof one or two rows deep, a whole-piece band would be the whole roof, so the pieces that would be edging with no plain piece beside them are built from blocks at the same slope instead, with the one-block strip; between the strips, 2 m pieces go wherever they fit (the roof's own 2 m pieces, or those of the same roof in 2 m pieces on a 4 m roof, as they are or moved half a meter up the slope, wholly on the roof's surface and clear of the strips), so fewer blocks are needed. Only the roof's top layer is edged; a double or triple roof's layers under it keep their materials. On an L, T or cross roof, once any arm has to be built that way (an arm one or two rows deep), every arm's edging is, so the roof has one style of edging rather than whole pieces on some arms and strips on others. Pieces built from blocks this way follow the pieces' own steps (a 45° piece is a staircase one block thick, 9 steps of 8 blocks for a Roof Side 4M, as Embervale records a placed piece with blocks deleted), each column filled down to its lowest neighbor's top so neighbors share a face and the underside is even, and a piece's lowest step beside the blocks gets a block under it (hidden under the piece) so no gap shows where blocks and pieces meet.
- **Layers (double and triple thick).** Every roof can be **Double thick**: a second layer under the roof in its own **Inside material** (any roof or building-block material). **Triple thick** puts a second layer of the roof's own material right under it (the roof's pieces again 0.5 m lower, or one block under a block roof; it has no drop setting) and the inside layer under that, its drop counted from the second layer. With Recede on, the second layer recedes like the inside layer, with its own choice of gable ends (**Second roof layer recedes at gable ends**).
  - **Inside layer drop** sets how far under the roof it sits: 0 to 5 blocks (0.5 m each). A roof of pieces' layer sits that many blocks under it plus one more against bleeding through (so 0 is half a meter under, which may bleed through; 1, the default, is 1 m); a block roof's layer touches the roof at 0 and 1 and sits a block lower for each block over 1. The extra block keeps the inside material from bleeding through where pieces meet (the game appears to put pieces on the 0.5 m grid, rounding down, so everything in the inside layer stays on the grid), and its pieces are written to the file before the roof's own (where pieces overlap, the game draws both materials unless the top piece comes later). Both were seen in game on 2026-11-03/04.
  - A block roof's inside layer is every block under the roof that touches it: under each column, and beside the columns of a steep slope, whose sides face the space under the roof too, so none of the roof's material shows from below. A larger drop moves it that many blocks lower.
  - The layers under the roof always end level with the roof's eaves (flush): at 45°, moving a piece uphill is the same slope as moving it down, so their pieces along the eaves move in rather than down, and pieces elsewhere move in just enough not to reach below the eaves; block layers leave out what would hang below them (on gentle slopes, whose first columns are level with the eave, they start a little further in). A piece that would poke through the far side of the ridge can't move in; a blueprint can't record blocks taken out of a piece (Embervale records placements, not later edits; confirmed 2026-11-04; its author plans to add this), so such pieces are replaced by smaller ones in the same space: a 4 m roof's layer is laid in 2 m pieces, and 2 m pieces become blocks.
  - **Recede bottom layer**: **No** (flush), or **One block from the edges**: the inside layer comes in one block further at the eaves, and both it and a triple-thick roof's second layer come in a block at the gable ends chosen (**Inside layer recedes at gable ends**, **Second roof layer recedes at gable ends**: both, neither, or just the -x / -z or +x / +z end on gables and sheds; yes / no for all of an L, T or cross roof's gable ends). The second layer stays flush at the eaves. A shed's high side and the junctions of L, T and cross roofs never recede.
- **Sides.** Gables and hips can be asymmetric. **Saltbox** gives one side 1 to 8 extra rows, so it runs lower at the same slope (with roof pieces at 45°, or blocks). A gable's **Off-center ridge** moves the ridge toward +z or −z in 0.5 m steps with both eaves level, giving each side its own slope; it is always built from blocks, since roof pieces only come at 45°. The angle (or height) applies to the longer side.
- **Ridges.** At 45° the game fills the seam along a ridge itself, so no ridge caps are needed. Block roofs always end each slope with a one-block step up to a ridge one column wide on each side, the only ridge shape the game draws its ridge texture on, and spread the other steps evenly up the slope.
- Block roofs are merged into larger pieces on export like any other blocks.

### Pipe runs

**Pipe run**, under Pipes in the Add menu, is a whole pipe in one shape, built to hold water (Enshrouded pumps water through sealed pipes). Every part of a run is built and hollowed together, so joints seal at any angle, and the pipe is worked out on the world grid after its rotation, so a turned pipe stays sealed too.

- **Inner radius** is the water channel: 0.25 m (one block across, the narrowest), or 0.5 m, 1 m, 1.5 m and so on (radii between, like 0.75 or 1.25, would sit the channel half a block off the wall's grid, so they aren't offered; the arrows step straight between allowed values, and a typed one settles on the nearest); **Wall thickness** (1 to 4 blocks) is added outside it. Every block sharing a face with the channel is wall, so there is no face-to-face gap out of the pipe except its open ends. Blocks that touch only at an edge or corner hold water (tested in game), so the wall doesn't close those, which keeps it about a third lighter. A pump fills a pipe only up to its own height (tested in game), so put the pump at or above the highest point the water has to reach.
- **Start**, **End** and **Branch ends**: open, end cap, flange (a thicker band of **Flange thickness** blocks over **Flange length** from the end), bell mouth (the channel flares to **Bell mouth radius** over **Bell mouth length**), or tank connector (a flat ring of **Tank connector radius** flush with the end, for setting against a wall or tank).
- **Toward** (which way a fitting turns or dips): **Up** is always toward +y and **Down** toward -y, and **Left** and **Right** are level, as seen looking along the pipe the way it runs, wherever the pipe has been (after a joint's branch, a trap or a helix too). Heading straight up or down there is no level left or right, so they stay as they were just before. Picking a U-trap sets its Toward to Down.
- Up to 8 **segments**, each a fitting, in order from the start (the run heads +x, up +y, until turned; with **Start end faces** set to Up, it heads straight down from a start end facing up, which makes a fill end you can pour into):
  - **Straight** (**Length**), **Turn** (180°, 120°, 90°, 60°, 45° or 30°, **Toward** left, right, up or down, with a **Bend radius**; 0 is the tightest), **S-bend** (two opposite turns shifting the pipe **Offset sideways**), **U-trap** (down **Depth of the dip**, round, and back up), **Helix** (**Turns**, **Helix radius**, **Rise per turn**, round an axis along the pipe).
  - **Reducer** (to a **New inner radius** over its length; concentric, a cone, or eccentric, flat on the side chosen), **Coupling** (a sleeve one flange thick over its length).
  - **T joint**, **Cross**, **45° lateral**, **Y joint** (the run carries on round one arm, the other is a branch) and **Manifold** (**Outlets** in a row, on one side or on **both sides** in pairs, **Spacing between outlets** blocks apart: 0 puts them as close as their walls allow, neighbors sharing one wall block, and each block more adds 0.5 m between them; its length follows from that), each branch starting with a **Branch length** stub.
- **Branches carry on.** A joint's side outlet can have segments of its own, a branch, built from the joint's stub onward like the run itself, ending in its own **End fitting** (open, end cap or flange; the run's **Branch ends** until set). In the shape list a joint is a green subfolder of its branch's segments (a cross or manifold, with several outlets, holds a **Branch 1**, **Branch 2**, ... subfolder for each). Selecting a joint shows its settings and, under them, tabs for its branch: **Branch end**, each of its segments and **+ Segment N** to add one (with several outlets, a tab per branch first). A branch's own joints can branch again, up to 15 levels below the run; at the deepest level there are no joints to pick.
- A segment set to **None** ends the run; the next segment's settings appear once the one before it is a fitting.
- **In the shape list** a pipe run is a green folder of its segments ("Segment 2: Turn 90° right"), opened and closed with its arrow (or the right and left arrow keys); the number beside it is how many segments it has. Click a segment to see just that segment's settings. Select the pipe run itself for its settings in tabs: **Pipe** (name, folder, combine, position, rotation, radius, wall, ends and the rest, material), one tab per segment, and **+ Segment N** to add a fitting at the end. The pipe still moves as one shape: drag its row, not a segment's.

**Water splitter**, also under Pipes, splits one stream into many: a fill end facing up, a drop, a level run, then the outlets in pairs, one left and one right, as close together as their walls allow (neighbors share one wall block). All the outlets are open, level with each other and the same length; an odd count adds one more draining straight on, and an even count caps the far end.

- **Inner radius** and **Wall thickness**, as for a pipe run (it starts at 0.25 m, one block across).
- **Outlets** (2 to 32), **Outlet length**, **Spacing between outlets** (blocks; 0 is as close as their walls allow).
- **Input length**: from the fill end to the first pair of outlets. **Input height**: how far the fill end is above the outlets (keep it above them; water won't rise past where it's poured or pumped in).

### Gables

**Gable (fills under a roof end)**, under Roofs in the Add menu, is the wall that closes the gap under one end of a gable or shed roof, or under any gable-ended arm of an L, T or cross roof: blocks stair-stepping up right under the roof's lowest layer, so nothing shows between the wall and the roof.

- **Match a roof** lists the ends of every gable and shed roof in the build, and every L, T and cross roof arm that ends in a gable (named by the way they face, such as "end toward -x" or "Bar, +x arm, end toward +x"). Matched to an arm, the gable copies that whole roof (every arm, its layers, drop, recede and edging) and is worked out from it, so it fits even arms of different widths, heights, angles and offsets; its own roof settings are then hidden, with a note saying which arm it fits and a button to go back to its own settings. An arm taller than the arm straight across from it (a T's bar, a cross's pairs) also offers its **inner end**, the open gable where it ends at the junction above the lower arm ("Bar, +x arm, inner end above the -x arm"): that gable stands on the lower arm's roof and fills up to the taller arm's underside, and where the taller arm is wider than the lower one it reaches down to the eaves' level beside it. Picking one copies that roof's settings into the gable and puts it at that end, turned with the roof. It is a copy: edit the roof later and match again, or change the gable's own settings by hand.
- **Thickness** (1 to 16 blocks) is how far it reaches in along the ridge from the roof's end. **Outer face** says which end of the ridge it sits at (the slices it takes; under a receded layer they differ). **Recede into the roof** (0 to 32 blocks) pushes it that far further in along the ridge (the peak line), still filling right up under the roof and down to the eaves there, for a wall set back under the overhang. The shape stays where it was matched (its box grows inward to take the blocks), so changing Recede afterward moves the wall without matching again.
- **Roof it fits under** holds the roof settings it is worked out from: **Gable** or **Shed**, the angle (45° roof pieces, 22.5°, 33.3°, 67.5°, set by height, a custom angle or a rise / run), roof height, piece size, rows, sides (saltbox, off-center ridge), layers (single, double or triple thick, the inside layer's drop and recede, and whether each layer recedes at this end) and edging. Matching fills these in; typing them in gives a gable for a roof you haven't placed. The roof's edging isn't shown (it hardly changes the space under the roof), but Match a roof copies it.
- The gable is worked out from a roof built with those settings, so it fits every angle and layer setting exactly: under roof blocks it stops just below the lowest one, and under roof pieces each block's top stays at or below the piece's top surface.
- **Blocks touching roof pieces** are in the roof's own material by default (the material of the piece right above, so the inside layer's on a double-thick roof of pieces): a different material right under the tiles shows through them, the roof's own does not, as builders do in game. Set it to the gable's material to turn this off. Under roof blocks nothing changes. **Roof material**, **Inside material** and **Edging material** under Roof it fits under say which materials those are (Match a roof copies them).
- It is an ordinary block shape otherwise: move it anywhere, turn it, combine it, or give it its own material. It is always solid (no Filled / Hollow).

## Privacy and security

ShapeForge makes no network connections. Its window runs sandboxed, with no access to your computer except through a handful of requests to the app itself: export, save, open, import and reopen. Open, import and export always go through Windows' own file dialogs. Save without a dialog, and reopening last session's files, work only for files you picked in an Open or Save dialog; the app keeps that list in `known-projects.json` in its settings folder (`%APPDATA%\shapeforge`). The app asks for no permissions (camera, microphone, location and the like are refused), embeds no other web pages, and opens links (the README's, the About box's e-mail address) in your browser or mail program, never in its own window. Run `npm audit` after `npm install` to check the libraries it's built on.

## File format notes

- Each cube is written unrotated, with `pos` at its minimum corner; the model is shifted so its lowest corner is at (0, 0, 0).
- When reading, every known piece type is expanded into the 0.5 m cells it covers, rotating around its `pos` corner. Pieces of unknown types (props, or block types added to the game later) are left out and counted in the import message. Roof pieces become regular blocks when exported again.
- With larger pieces on, the export packs each material separately, biggest pieces first, using only orientations confirmed in game: unrotated and turned 90° around the vertical axis. (The game drops large pieces whose length is turned to point upward.) Door Frames, which have their own notched profile, and roof pieces are never used. Every export reads back block for block identical to the design; `tests/merge.test.ts` checks this for every shape.
- Roof Sides (2M id 2482289794, 4M id 1083013738) slope along x when unrotated, high at −x with a 0.5 m eave past the run at +x, and are 2 m (4 m) wide along z, so they sit side by side along the ridge without overlap. Turned 90° around y the high side faces +z. Rows step 2 m (4 m) down and out, each eave lying over the row below. They are written with `flag` 1, turned only around the vertical axis; `tests/roofs.test.ts` checks the directions confirmed in Embervale.
- Roof Outer Corners (2M 985540864, 4M 3000989055) and Inner Corners (2M 3722239847, 4M 2297453360) are square, run + 0.5 on a side. Unrotated, an Outer Corner peaks at its −x, +z corner and slopes down toward +x and −z; an Inner Corner is high along its −x and −z edges and slopes down toward +x and +z. `tests/roofs.test.ts` checks a hip roof end against one built by hand in game (`tests/fixtures/rooftest_hip.ebblueprint`).
- Block roofs (angles other than 45°) use the same plan as at 45° and the same distance to the eaves, measured per 0.5 m column with a two-pass chessboard distance transform; the last step under the ridge is one up and one across, the steps below it are spread evenly (flat stretches on gentle slopes, climbs on steep ones, never differing by more than one), and each column is filled down to its lowest neighbor's top, so neighboring columns always share a face. `tests/roofs.test.ts` checks the slope, the even steps, that there are no gaps, and that the plan matches the 45° roof at every turn.
- L, T and cross roofs are laid out by distance to the eaves: each point is as high as its square-wise distance to the nearest eave (gable ends don't count), which puts hips on outside bends and valleys on inside ones. Each cell gets the piece that matches which of its corners are high: two neighboring corners make a Roof Side, one an Outer Corner, three an Inner Corner. Sheds, gables and hips are single wings laid out the same way (a shed's high side counts as open); this gave exactly the earlier hand-written layouts in all 1,152 configurations compared, and a hip-ended T contains the hand-built recording piece for piece; the tests check both. When a blueprint is imported, its roof pieces are left out (they aren't blocks).
- `contentSha256` is a SHA-256 of the pieces block. Embervale does not check it.
- The game's world is the mirror image of ShapeForge's along z (found from a numbered die whose 7 came out back to front in Embervale Toolkit). So exports are flipped along z (blocks cell by cell; roof pieces turned to point the flipped way on the flipped box, as Roof Sides are the same either side along the ridge and both corners the same either side of their diagonal) and imports flipped back (`handedness.ts`): what ShapeForge shows is what lands in game, text, dice, turns and pipe directions included. The notes on piece orientation here are in the file's own coordinates. Projects saved before 0.44.0 have their imported layers flipped once when opened, so they come out in game as they did.
- Embervale places a blueprint with its first piece in place of the block you put down; `anchorMode` and `anchor` in the file make no difference (tested with `bottom`, `ground`, `lowest`, `corner1` and `custom`), and ShapeForge writes `"anchor": [0,0,0]` and no `anchorMode`. `lift` (meters, up positive) is honoured. The anchor block is written first; a marker block becomes the lowest corner when it's below or in front of the build.
- Extra top-level keys make Embervale reject a file, so nothing app-specific is stored in the blueprint. The editable design lives in the separate `.shapeforge` project file.
- Project files hold a format name, a version number, the blueprint name, the anchor and lift (when set), the shape list (each shape's name and folder with it) and the folders. Missing or out-of-range values are replaced with defaults when opened, so hand-edited files still load.
